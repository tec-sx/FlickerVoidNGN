# Physics

- One physics engine for the whole game (owner, 2026-11-25): Jolt, through JoltPhysicsSharp, chosen over Bepu, Box3D and PhysX for its finished vehicles and character controller (the spike's report is linked from issue #151). The move is task 1.0 of the editor creation tools' milestone 1, in three pull requests: the interface in engine types only, then the implementation on Jolt, then hull and triangle colliders, hinges and sliders. Until the second, the implementation is BepuPhysics.
- The library is this module's detail: `IPhysicsSystem` (a fixed system and service, added by `game.AddPhysics()`) and the components speak engine types only, so other modules and tests never reach the library and a later move touches this module alone. It casts rays (`RayCast`, the nearest body's entity, point, normal and distance, optionally ignoring one entity's body) and answers `HasBody`, `IsAwake` and `BodyCount`.
- Scene components: `rigidBody` (`RigidBody`: a collider, a mass, kinematic or dynamic, and whether paths go around it) and `staticBody` (`StaticBody`: a collider, an obstacle by default). Colliders are `box`, `sphere` and `capsule`, chosen by `type`, with an `offset` from the entity. Each step adds bodies for new components, removes those whose entity or component is gone, moves kinematic and static bodies to transforms that moved, steps, and copies the poses of awake dynamic bodies to their transforms. A body at rest falls asleep. Solid greyboxes without a body of their own get a static box of their size while playing.
