# Saves

- Saves (`Runtime/Saves`, ported from FVStorySystem's save subsystem; `SceneHost` adds them to every game, in `FlickerVoid/<title>/Saves` under the user's local application data unless `--saves` names a folder) write slots as `.fvsave` JSON (`SaveGame`: `SaveMetadata` with version, slot, time, play time and checkpoint; the facts; `Entities`, the state of each `saveable` entity by its id; `Destroyed`, the ids of saveable entities that were gone; `States`, game-wide state by key). What is saved is registered on `Game.SaveStates` by the modules, like data types on `Game.Data`: `AddComponent<T>` keeps a plain component as it is through its `JsonTypeInfo` (set back on load, removed from an entity that had none), `Add<TState>` keeps a module's own state of each saveable entity (an interactable's uses, a scannable scanned) and `AddGlobal<TState>` keeps game-wide state, both written with `Game.Data`'s options (so their types need a resolver added there, and polymorphic values such as item instance data, registered with `RegisterDerived`, work), read back in the order added; definitions are saved by their files (`DataAssets.TryGetPath`); entities without a `Saveable` id (placed in the scene with one unique there, like Unreal's save ids) are not saved, and entity references are never saved. Saved: transforms (Runtime), walking and turning (`destination`, `facing`), locks, toggles and interactables, inventories (stacks with their ids and instance data, money), worn items (re-worn, so granted tags follow), pickups and lootables, attributes (base values, and modifiers with their handles), map markers' discovery and the waypoint and tracked marker (and whatever a game registers, such as Bleeders' door hinges and scans). `DialogueSystem` holds `Save.Block.Dialogue` while a conversation runs and ends any conversation when a save loads. `SaveSystem` (a service) saves, loads, deletes and lists slots (newest first), keeps play time across loads, refuses to save while a block tag is held (`AddBlock`), restores the facts, then the states (destroying saveable entities that were gone), then raises `Loaded`; a missing, broken or newer save loads nothing. Quests come back with the facts, and `QuestSystem` restarts the flows of the active ones on `Loaded`. The stage 7 gate is Bleeders' `StoryLoopTests`.
- With scene travel, saves keep the scenes the game left as they were left (`SaveGame.Scenes`), carry the travellers' state to the next scene, and load by travelling to the save's scene (`SaveGame.Scene`), so the world is spawned anew before the save is read back; `Loading` is raised first, so modules let go of what they run. Loads replace entities, so a key press defers one to before the next tick (`Game.Defer`).
