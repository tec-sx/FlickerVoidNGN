# Flow graphs

- Flow graphs (`.fvflow`, the `Flow` module over Runtime, like the Unreal Flow plugin) are scripted sequences for story, quests and dialogue: nodes linked output pin to input pin. A node derives from `FlowNode<TOut>` (one input, `In`) or `FlowNode<TIn, TOut>`, whose enums are its pins (`FlowInput`, `FlowOutput`, `NoPins`, or its own nested `Out`), so it triggers `context.Trigger(Out.True)` with no pin strings; files name pins by enum name, and a `FlowRun` resolves the links to pin indices once, throwing for a missing node or pin. Each node type is registered on `Game.Data` with `RegisterDerived<FlowNode, T>` and named by `$type`; nodes without inputs run as the run starts. A game project's nodes are classes marked `[FlowNodeType("name")]`, registered by the `FlowNodeTypes.Register(game.Data)` that the `Generators` tool (`Source/Tools/Generators`, Roslyn source generators referenced as an analyzer, with their rules listed in `AnalyzerReleases.Unshipped.md`) writes into the project, beside its JSON context (`AddResolver`), which lists each node with `[JsonSerializable]` because System.Text.Json's generator can't see another generator's output. The editor opens a `.fvflow` from the asset browser (New Flow creates one with a start node) in a `FlowEditorWindow`: an endless canvas (`FlowCanvasView`: right or middle drag pans, the wheel zooms about the mouse, F frames the selected node or all, and it opens framed; `FlowGrid` draws faint lines under it) over `FlowGraphViewModel` (Core: nodes laid out in fixed rows so pins sit where `FlowPinViewModel.Point` says, wires drawn by `FlowWires`; Shift+A adds a node of any registered type, grouped by module, right-click offers options, drag nodes, drag from a pin (grabbed within `GrabRadius`) and drop on or near a node to wire it to its nearest fitting pin (`FindDropTarget`, the wire snaps while dragging), drop a wire on empty space to add a node wired to it (`GetAddChoices`), Delete removes) beside the selected node's form (`DataObjectViewModel`, its id and place hidden); edits are held by `UnsavedContent` through `FlowDocument` and written with `FlowGraphs.Write`. `SceneHost` adds flow to every game and serves `FlowGraphs`. `game.AddFlow()` registers the core nodes (`start`, `finish`, `branch`, `applyEffects`, `waitForConditions`) and the `flow` schema; `FlowGraphs` reads a file and starts a `FlowRun` against a `ConditionContext`. Nodes are shared data: a run keeps the active nodes, passes signals along links in order, tells active nodes when a fact changes, and stops a trigger that loops. Gameplay's condition and effect types (`fact`, `group`) are registered by `Game` itself, so any data file can hold condition sets and effect lists.
- Runs resume: `FlowRun.GetActiveIds()` names the active nodes and `Resume(ids)` starts a run with them active again, each through its node's `Resume` (by default it executes again; `switchShot` and `fade` carry on), so saves keep where flows were; `SetConditions` moves a running run to another context, such as a new player.
