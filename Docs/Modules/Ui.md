# The game's interface

- The game's interface (the `Ui` module over Hosting; owner, 2026-11-21: Avalonia drawn into the game) is Avalonia controls, AXAML and MVVM like the editor, on Avalonia's headless platform with Skia (`UiPlatform.Start<TApplication>()` once, with the game's application holding its styles): a `UiSurface` holds the controls in a window never shown on screen, is handed the window's mouse, keys and typed text each frame and draws them into memory, transparent where there are no controls (premultiplied BGRA): straight into a `RenderTargetBitmap` it keeps, as Avalonia's headless frame capture renders several times slower and makes a new bitmap each frame, and `Draw` says whether the drawing differs from the last. `GameUi` (an `IFrameOverlay`) follows the window's size and draws the surface over the scene each frame (`UiRenderer`: only a changed drawing goes through an upload buffer into the texture of the next of three frame slots, so an unchanged interface uploads nothing, and `Shaders/GameUi.hlsl` blends the latest over the target, made linear on an sRGB target). Stages (owner, 2026-11-21: 3D in the interface, reused for inspect) are small scenes shown in the interface: a `Stage` loads its `.fvscene` (models, lights, a camera, a `SceneMood`) into a world of its own, spins its `turntable`s (`Turntable`: speed, drag speed; `TurntableSystem` spins them in the game's world too) and animates its meshes, and while a `StageView` control shows it renders it with a `SceneRenderer` of its own on the game's device and reads it back into a bitmap; dragging across the view turns it. `game.AddTurntables()` registers the component (in a game module, so the editor knows it) and `game.AddStages(device, content)` adds `StageSystem`, which creates and updates them. Post-processing writes coverage into alpha (0 where nothing was drawn), so a stage shows over the interface. Several overlays draw as one through `FrameOverlays` (Hosting), the debug interface last. Overlays that are `IPointerCapture`s (`GameUi` over a control, `DebugUi` when it wants the mouse) are added to `InputActions.PointerCaptures`, and while one captures the pointer, button bindings read as up, so a click on the interface never reaches the world.
